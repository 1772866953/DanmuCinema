# WPF 桌面界面与按需窗口

DanmuCinema 默认启动 WPF 界面。后台控制器、视频服务、弹幕网关、下载和定时任务与窗口生命周期分离，在同一进程内运行。

桌面代码位于 `desktop/`，复用 `src/` 的服务、接口、匹配、下载、媒体库、搜索历史和调度状态机。当前使用 Windows 自带的 .NET Framework 4.8 WPF，继续使用已有的构建工具和加密配置格式；无需下载 SDK、WebView 或额外 UI 运行库。界面使用深蓝底色、紫青渐变强调、分层卡片、背景光晕、统一圆角控件、主题提示框和虚拟化列表。背景模糊仅用于装饰，不作用于文字或控件树。页面和页签文字始终保持不透明、像素对齐，切换动画只作用于装饰与悬停层，避免分数位移与淡入造成字体模糊。动画遵循 Windows 的动画偏好。

## 窗口与服务

- 普通启动创建主窗口；`--tray --start` 只创建后台控制器与托盘，并启动服务。
- 自绘标题栏保留原生窗口样式，使用加粗矢量按钮和系统最小化/最大化/还原命令，允许 DWM 窗口过渡；若 Windows 关闭动画，则遵循系统设置。
- 最小化按钮保留任务栏最小化语义；关闭按钮按照偏好进入托盘或停止服务退出。
- 进入托盘时关闭主窗口及其弹窗，停止界面计时器，解除日志/控制器订阅，清理 XAML 名称索引和控件树。托盘收起不弹通知。
- `Application.ShutdownMode` 使用 `OnExplicitShutdown`；关闭所有窗口不会退出进程。
- 托盘双击、菜单和重复运行快捷方式均恢复窗口。重复启动通过具名事件通知控制器，不轮询事件。
- 定时器只在任务有效时运行；前台服务状态每 4 秒查询，托盘每 30 秒检查本项目的服务存活。托盘不查询播放会话、不刷新媒体列表。
- 批量下载由控制器持有。关闭下载窗口或进入托盘不会取消任务；恢复窗口或点击“下载任务”可查看进度。停止下载只取消未完成部分。

## 状态恢复

窗口位置、普通窗口尺寸和最大化状态沿用 `data/window-state.json`，保存物理像素并在 WPF 恢复时换算为设备无关单位；屏幕变化时移回可见区域。冷启动恢复窗口尺寸与最大化状态。

当前进程中的页面、目录前进/后退历史、筛选、排序、勾选、页面滚动、未保存设置和匹配候选使用独立的数据对象保存。进入托盘时释放控件，再次打开时重建控件并应用这些状态。未提交的密码不持久化，也不在托盘恢复时重建。

## 功能保持

- 媒体库默认文件夹视图、文件名自然排序、日期/大小/类型/码率排序、MB 大小、筛选、多选、拖动区间圈选及全选。
- 搜索历史自动展开、逐条删除、全部清空，以及目录前进/后退和鼠标侧键。历史弹层不捕获鼠标，点击编辑区可直接定位光标；外部点击仅关闭弹层，不阻止目标控件操作。弹层关闭与窗口释放解除所有回调。
- 多来源联合搜索、动漫筛选、智能匹配、单集/整季/已选影片重新关联、批量预览/下载/取消、XML 导出和来源记录。
- 官方 API 仅提供启用复选框，凭证继续从不入库的 `config/dandanplay.json` 读取。
- 弹幕写入复用已有原子覆盖逻辑，不生成 XML BAK；请求失败和空弹幕不破坏已有文件。
- 原画策略、端口、账号初始化、添加媒体库、组件安装、防火墙、开机启动、关闭偏好、定时电源操作和运行日志。
- 现有 Jellyfin/Filebar 兼容和上游弹幕逻辑未替换。

## 构建与验证

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Test
```

先执行现有业务测试，再执行 `--wpf-test`。WPF 测试使用 `tests/output/` 的独立配置和模拟影片，验证实际控件绑定、全选、窗口恢复、最大化关闭、控件回收、首次点击历史不捕获鼠标、编辑区命中、正文无位移/透明动画、原生最大化还原、主题提示框取消与释放、匹配弹窗重建，以及界面释放期间后台继续写入弹幕。测试不连接真实服务，不执行关机等系统操作。测试输出和界面渲染 PNG 不进入仓库。

资源回收测试中的强制 GC 仅用于判断弱引用，生产运行不强制 GC、不裁剪工作集。进入托盘会释放控件和原生窗口资源，但 CLR/WPF 的运行库和缓存可能保留；实际内存回落时间由运行时决定。Jellyfin 扫描、播放和转码的资源不包含在界面优化中。

原 WinForms 界面暂时保留为兼容回退与旧控件回归测试，可用 `--legacy-ui` 启动；普通快捷方式和开机启动均使用 WPF。
