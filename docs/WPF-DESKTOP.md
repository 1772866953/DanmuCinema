# WPF 桌面界面与按需窗口

DanmuCinema 默认启动 WPF 界面。后台控制器、视频服务、弹幕网关、下载和定时任务与窗口生命周期分离，在同一进程内运行。

桌面代码位于 `desktop/`，复用 `src/` 的服务、接口、匹配、下载、媒体库、搜索历史和调度状态机。当前使用 Windows 自带的 .NET Framework 4.8 WPF，继续使用已有的构建工具和加密配置格式；无需下载 SDK、WebView 或额外 UI 运行库。界面使用深蓝底色、紫青渐变强调、分层卡片、背景光晕、统一圆角控件、主题提示框和虚拟化列表。背景光晕使用冻结的径向渐变，不创建动态模糊效果缓冲区；弹窗与原生合成背景始终不透明，避免切换激活时闪白。页面和页签文字始终保持不透明、像素对齐，切换动画只作用于装饰与悬停层，避免分数位移与淡入造成字体模糊。动画遵循 Windows 的动画偏好。

## 窗口与服务

- 普通启动创建主窗口；`--tray --start` 只创建后台控制器与托盘，并启动服务。
- 自绘标题栏保留原生窗口样式，使用加粗矢量按钮和系统最小化/最大化/还原命令，允许 DWM 窗口过渡；若 Windows 关闭动画，则遵循系统设置。
- 最小化按钮保留任务栏最小化语义；关闭按钮按照偏好进入托盘或停止服务退出。
- 进入托盘时关闭主窗口及其弹窗，停止界面计时器，解除日志/控制器订阅，清理 XAML 名称索引和控件树。托盘收起不弹通知。
- `Application.ShutdownMode` 使用 `OnExplicitShutdown`；关闭所有窗口不会退出进程。
- 托盘双击、菜单和重复运行快捷方式均恢复窗口。重复启动通过具名事件通知控制器，不轮询事件。
- 定时电源计时器只在任务有效时运行；前台服务状态每 4 秒查询，托盘每 30 秒检查本项目的服务存活。服务运行期间，独立后台任务每 3 秒读取本机 Jellyfin 播放会话，托盘中继续工作；空闲不会调用外部弹幕接口，不刷新媒体列表。
- 批量下载由控制器持有。关闭下载窗口或进入托盘不会取消任务；恢复窗口或点击“下载任务”可查看进度。停止下载只取消未完成部分。

## 状态恢复

窗口位置、普通窗口尺寸和最大化状态沿用 `data/window-state.json`，保存物理像素并在 WPF 恢复时换算为设备无关单位；屏幕变化时移回可见区域。冷启动恢复窗口尺寸与最大化状态。

当前进程中的页面、目录前进/后退历史、筛选、排序、勾选、页面滚动、未保存设置和匹配候选使用独立的数据对象保存。进入托盘时释放控件，再次打开时重建控件并应用这些状态。未提交的密码不持久化，也不在托盘恢复时重建。

## 功能保持

- 媒体库默认真实目录层级，子目录不会提升到根层；列表按圆角轮廓裁剪。支持文件名自然排序、日期/大小/类型/码率排序、MB 大小、筛选、多选、拖动区间圈选及全选。
- 搜索历史自动展开、逐条删除、全部清空，以及目录前进/后退和鼠标侧键；不显示前进、后退、返回文件夹三个按钮。历史弹层不捕获鼠标，点击编辑区可直接定位光标；外部点击仅关闭弹层，不阻止目标控件操作。弹层关闭与窗口释放解除所有回调。
- 媒体列表右键支持删除整个文件夹、视频或弹幕，可应用于当前选中行。确认框列出完整目标路径及删除范围，取消不修改文件。文件夹删除包括其全部内容；视频删除保留同名弹幕；弹幕删除仅移除同名 XML。操作为永久删除，不经过回收站。仅允许配置的媒体目录内部目标，禁止删除媒体根目录和经过目录链接/符号链接的目标，确认后重新检查路径与文件变化。列表立即更新，Jellyfin 运行时提交媒体库扫描；当前观看中删除的弹幕不会立刻由后台重新生成，播放结束后恢复自动匹配。
- 多来源联合搜索、动漫筛选、智能匹配、单集/整季/已选影片重新关联、批量预览/下载/取消、XML 导出和来源记录。
- 官方 API 仅提供启用复选框，凭证继续从不入库的 `config/dandanplay.json` 读取。
- 弹幕写入复用已有原子覆盖逻辑，不生成 XML BAK；请求失败和空弹幕不破坏已有文件。
- 原画策略、端口、账号初始化、添加媒体库、组件安装、防火墙、开机启动、关闭偏好、定时电源操作和运行日志。
- 现有 Jellyfin/Filebar 兼容和上游弹幕逻辑未替换。

## 官方识别与自动弹幕

启用官方源后，手动匹配优先识别本地文件：只读取视频前 16 MiB 计算 MD5，先提交 `hashOnly`，未命中再提交 `fileNameOnly`。hash 唯一命中优先级最高；文件名候选必须核对作品、季度、集号且唯一可靠才会自动采用，有歧义时保留手动选择。联合搜索优先展示官方源，也保留其他已启用来源。

iPad 通过本项目 Jellyfin 播放时，后台检测正在播放的视频及媒体版本。有非空同名 XML 时保留该文件和手动来源，不请求官方接口；缺少 XML 时识别、下载并原子写入视频旁。自动写入与手动覆盖串行，避免自动任务覆盖已保存的手动弹幕。同一影片事件合并，失败后有 10 分钟冷却，停止服务取消后台任务。现有 XML 不会因缓存过期自动刷新。

独立的 DanmuCinema Playback 插件在已授权的 `/Items/{id}/PlaybackInfo`、`/api/danmu/{id}` 和 `/raw` 动作执行前，通过本机密钥桥等待当前影片的弹幕准备。这样客户端首次读取弹幕信息时即可取得已经保存的 XML。后台轮询作为补充继续保留；两种触发共用同一准备任务。插件不修改第三方 Danmu 插件，也不拦截视频流或预取整库。

首次联网可能增加进入播放的等待时间，插件最长等待 35 秒；来源不可用、没有可靠匹配或超时则放行播放，不保证失败情况下仍有弹幕。已进入播放的客户端不会被强制热加载。新插件安装后需重新启动 Jellyfin 服务才会生效；正在播放时不自动重启。`data/playback-bridge.json` 由网关启动时写入，密钥每次启动重新生成，仅接受本机连接；它不包含官方接口凭证，也不进入 Git。

手动识别成功后自动读取完整作品集数，单击其他来源也自动读集数。勾选多集默认打开“已选影片”页签；可匹配条目默认全部勾选。未选择影片时，搜索后自动关联唯一同名、同季度的本地目录；有多个版本或无法可靠判断时，使用弹窗的“本地季度”选择再预览整季。文件名末尾括号集号优先于错误的媒体元数据，例如 `Hyakkano - 25 (1)` 至 `(12)` 按 1—12 集匹配，特别篇不混入普通集数。批量复选框直接绑定状态，不启动 DataGrid 编辑事务；重复预览会更新已打开的下载窗口。

本地 `config/dandanplay.json` 保存 AppId、经 Windows 当前用户 DPAPI 加密的 EncryptedAppSecret 和 CallbackUrl，文件被 Git 忽略。官方开放接口使用请求签名；回调地址只保存在本地配置，无需额外 OAuth 登录界面。弹幕加速跳转限制 HTTPS 官方域名，跳转请求不携带应用凭证。

## 缓存管理

官方搜索、作品详情、hash/文件名识别、弹幕响应成功后写入 `data/dandan-cache/`。每次先读本地有效缓存；再次匹配、下载与程序重启均可复用，并发相同请求只调用一次。失败响应不缓存。缓存键不包含密钥或签名，hash 识别键不受播放会话是否提供时长影响。

- 所有类型共用缓存管理页的“统一有效期”：1 个月、3 个月、半年、1 年、长期，默认 3 个月。
- 有效期按数据原始保存时间计算日历月，月末和闰年使用实际日期。设置保存在 `data/settings.json` 的 `CacheRetentionMonths`，0 表示长期。应用后立即影响已有缓存，不重写内容或发起接口请求；延长有效期可复用尚未删除的旧条目，缩短后过期条目仅在读取时失效或由“清理过期”删除。
- 旧版本的逐类型有效期由统一设置接管；长期不会因时间过期，仍受容量上限和手动删除规则约束。文件特征在内容或修改时间变化后重新计算。
- 总量最多 5000 条、256 MiB，超过上限按保存时间淘汰旧条目。
- 缓存管理页显示类型、内容、MB、保存时间与有效期，支持筛选、刷新、删除选中、清理过期及清空全部。
- 物理缓存按动漫名称存放在 `data/dandan-cache/<安全动漫名 · 短摘要>/`。识别结果、作品详情、弹幕和可关联的文件特征归入同一动漫；搜索按查询名归档，无法确定动漫的旧数据保留在“未分类缓存”。旧的扁平缓存读取时迁移，不丢弃内容、重置保存时间或重新请求 API。
- 缓存管理默认显示动漫文件夹，双击进入条目列表，点击路径返回；支持鼠标侧键前进/后退、驱动发送的浏览命令及 Alt + 左/右。目录历史和类型筛选在切页及托盘恢复后保留；访问新目录清除旧前进分支。右键可删除整个动漫缓存文件夹或单条缓存。
- 列表读取和删除在后台线程执行，切页或进入托盘会释放页面引用。
- 删除缓存不删除视频旁的 XML，也不会立即联网；仅在下次相关请求没有有效缓存时访问接口。

过期规则用于保留数据更新能力；有效缓存和已有 XML 的重复使用不消耗接口额度。缓存管理页不主动预取或刷新全部媒体库。

## 弹幕正文与窗口状态回归

- 各 JSON 弹幕源转换 XML 前清理 XML 1.0 禁止的空字符、控制字符及残缺 UTF-16；保留中文、emoji、合法换行与 XML 转义。仅含非法字符的弹幕跳过。旧的官方 JSON 缓存也走同一转换，不必清缓存或重发 API 请求；任意格式错误的外部 XML 仍拒绝解析，保持原有文件和外部实体防护。
- 来源/集数列表使用固定深色模板，应用主题同时提供深色系统控件画刷，避免禁用、加载、下载和模态提示时回退到系统白色背景。测试检查实际渲染像素，覆盖空闲重复刷新、启用/禁用以及三级模态提示下的列表和表格。
- 整季预览由来源窗口直接拥有；关闭后在原生窗口销毁完成时恢复直接父窗口的绘制与焦点。只有关闭前处于前台的弹窗恢复父窗口焦点，后台关闭不抢占其他应用。进入托盘时按从子到父的顺序释放弹窗，下载仍由后台控制器持有。
- 隔离回归覆盖普通/最大化窗口、切换其他应用、三级模态提示、依次点击二级与一级关闭按钮，以及含空字符弹幕的实际 12 集合成文件下载；检查原生可见状态、前台窗口和主窗口未触发关闭。

## 构建与验证

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Test
```

先执行现有业务测试，再执行 `--wpf-test`。测试使用 `tests/output/` 的独立配置、合成视频和模拟 HTTP 接口，验证 hash 优先与文件名回退、重复请求和重启离线缓存、播放触发与手动 XML 保留、并发合并及清理缓存。WPF 回归验证实际控件绑定、缓存页筛选与删除、提示换行、下载页签、矢量复选框、紧凑历史按钮、全选、窗口恢复和控件回收，并生成 96/144 DPI 渲染图。测试不连接真实服务，不执行关机或 Computer Use。测试输出和渲染图不进入仓库。

播放准备插件源码在 `plugin/PlaybackPreparation.cs`，目标 Jellyfin 12.1 / .NET 10。构建脚本复用 PowerShell 7.6 的 Roslyn 和本地 Jellyfin 程序集，无需下载 SDK 或 NuGet：`scripts/build-playback-plugin.ps1`，加 `-Install` 安装到本项目插件目录。`build.ps1` 在已有 Jellyfin 运行库时同步构建；首次组件安装脚本同时安装插件。`--integration-test` 会启动独立 Jellyfin，使用合成视频验证插件加载、首个弹幕链接、播放前等待、未授权请求、准备失败放行和视频 Range 直传；不调用真实官方接口，不操作正在运行的用户服务。

资源回收测试中的强制 GC 仅用于判断弱引用，生产运行不强制 GC、不裁剪工作集。进入托盘会释放控件和原生窗口资源，但 CLR/WPF 的运行库和缓存可能保留；实际内存回落时间由运行时决定。Jellyfin 扫描、播放和转码的资源不包含在界面优化中。

原 WinForms 界面暂时保留为兼容回退与旧控件回归测试，可用 `--legacy-ui` 启动；普通快捷方式和开机启动均使用 WPF。
